## 1. Introduction

This Statement of Work (SOW) defines the complete scope for **study, design, develop, test, commission, and warranty** of a **Complaint Management System (CMS)** for the **Karnataka State Commission for Women (KSCW)**.

The work is floated by **Karnataka State Electronics Development Corporation Limited (KEONICS)** through Invitation for Quotations (IFQ) No. **KSEDC/IT5/P180/2026-27 / Call 2 [E-290886]** dated **30.07.2026**, to appoint an agency for the CMS engagement.

The appointed agency shall deliver:

- Requirements study and approved design documentation (FRS, UI/UX & Workflow Design, Dashboard Design, technology stack, and infrastructure requirement documents)
- Development of **web application** and **mobile application**
- Unit, system, and integration testing
- Master and one-time transaction **data porting**
- User Acceptance Testing (UAT) support and UAT report
- **Safe-to-Host** certificate from a **CERT-In empaneled IT Security Auditor** (at no additional cost)
- Training, refresher training, handholding, and user manuals (document + video)
- Deployment and commissioning on servers and related infrastructure **provided by KSCW**
- **Warranty of 3 years** from the date of commissioning

**Document handling** and **workflow / escalation** are **embedded** in the complaint lifecycle and are not separate bid modules.

> **Indicative functional scope note (IFQ §4):** High-level functional requirements in this SOW are based on the IFQ indicative list. Final functional detail shall be determined after KSCW approval of the FRS, UI/UX & Workflow Design, and Dashboard Design documents. Nothing in that note reduces the agency’s obligation to complete study, design, build, test, commission, security audit, training, and warranty as stated in the IFQ.

## 2. Project Overview

KSCW requires a digital **Complaint Management System** to receive, categorize, route, track, escalate, notify, and monitor complaints through multiple channels, with role-based operations and management dashboards.

### 2.1 Engagement Item (IFQ Quotation Line)

| SI | Item | Quantity | Unit |
| -- | ---- | -------- | ---- |
| 1 | Study, design, develop, test, commission and warranty of Complaint Management System (CMS) | 1 | Lump sum |

### 2.2 Business Context

| Aspect | Description |
| ------ | ----------- |
| End client | Karnataka State Commission for Women (KSCW) |
| Issuing agency | KEONICS (Government of Karnataka Enterprise) |
| Solution | Complaint Management System (CMS) — web + mobile |
| Primary outcome | Digitized multi-channel complaint intake, routing, SLA tracking, notifications, dashboards, and MIS |
| Hosting | On servers and related infrastructure provided by KSCW |
| Delivery window | One (1) month from date of issue of supply order (working-day milestones as per IFQ) |
| Warranty | Three (3) years from commissioning |
| Contract period | Three (3) years and two (2) months (including warranty) |

### 2.3 Guiding Principles

1. **Study before build** — FRS, UI/UX & Workflow Design, and Dashboard Design must be presented, reviewed, and approved by KSCW before development proceeds on approved baseline.
2. **Multi-channel intake** — complaints may originate from web, mobile app, email, call center, and other channels agreed in FRS.
3. **Controlled processing** — categorization, auto-routing, role-based access, escalation, and SLA tracking govern complaint handling.
4. **Visibility** — dashboards, analytics, real-time monitoring, and MIS reports support operations and management.
5. **Secure go-live** — CERT-In empaneled Safe-to-Host is mandatory before / as part of commissioning timeline.
6. **Sustainment** — 3-year warranty covers defects, enhancements (as defined), operations support, backups, redeployment, and yearly security audits in years 2 and 3.

## 6. Consolidated Functional Modules

The CMS functional solution shall be delivered as **seven consolidated modules**.  
Document attachment / retrieval and workflow / escalation steps are **embedded** inside the complaint lifecycle modules — they are not bid as standalone modules.

> Final field-level and screen-level detail shall align to the **approved FRS, UI/UX & Workflow Design, and Dashboard Design**. The modules below organize the IFQ indicative requirements for delivery and estimation without inventing unrelated business domains.

### 01. User Access & Role Management

**Purpose:** Provide secure authentication and role-based access for CMS users (Admin, Supervisor, Operator, and other roles defined in FRS).

**Functional requirements:**

- Create, update, activate / deactivate users.  
- Assign roles (at minimum Admin, Supervisor, Operator; additional roles as approved in FRS).  
- Enforce role-based permissions for menus, actions, and data visibility.  
- Support password / credential policies and session controls as defined in FRS / security requirements.  
- Maintain audit of privileged access changes.

**Acceptance criteria:**

| ID | Criterion |
| -- | --------- |
| M01-AC1 | Authorized Admin can create users and assign roles without code change. |
| M01-AC2 | Users can access only functions permitted by their role. |
| M01-AC3 | Deactivated users cannot log in. |
| M01-AC4 | Role / permission changes are auditable. |

#### Key capabilities (feature outline)

| Feature ID | Capability | Description |
| ---------- | ---------- | ----------- |
| F01-001 | User lifecycle management | Create, update, activate / deactivate CMS users |
| F01-002 | Role & permission assignment | Configure Admin, Supervisor, Operator and FRS-defined roles/permissions |
| F01-003 | Authentication & session control | Secure login and session handling for web and mobile |
| F01-004 | Access audit | Record privileged user/role changes for audit |

## 7. End-to-End Workflows

# F03-003 — Special Court and High Court orders

## Section 1 — Feature Specification

| Field | Value |
|---|---|
| **Feature ID** | F03-003 |
| **Feature Name** | Special Court and High Court orders |
| **Module** | 03 — Legal Knowledge Library & Search |

### Description
The user files an order with FE, CA, Accused, Advocates, Presiding Judge, date, case/petition and Act/section codes, then saves. A later search by judge, accused or case number opens that order.

### Business Objective
Store Special Court and High Court orders with the full referencing scheme including Accused, Advocates and Presiding Judge.

### Actors
Legal Cell; Advocate.

### User Journey
1. User opens the Court Orders Register (Special Court / High Court).
2. Files the order with FE, CA, Accused, Advocates, Presiding Judge, date, case/petition and Act/section codes.
3. Saves the original order file.
4. A later search by judge, accused or case number opens that order.

### Functional Capabilities
- Court Orders Register (Special Court and High Court)
- Order Filing form (Accused, Advocates, Presiding Judge, FE, CA, dates, Act/section)
- Retrieve by judge, accused or case number
- Original order unchanged on view
- No eValueI or Claim settlement order types

### Inputs
Order file; court type (Special/High); FE; CA; Accused; Advocates; Presiding Judge; date; case/petition; Act/section.

### Outputs
Filed order; coded metadata; retrieval hits.

### Business Rules
- Special Court Orders and High Court Orders use the full referencing scheme including Accused, Advocates and Presiding Judge.
- Search by judge, accused or case number must open the same original.
- Not GIS valuation or Claim payment orders.

### Validations
Court type required; case number as applicable; catalogue keywords for Accused/Advocate/Judge when coded.

### Calculations
None.

### Workflow
File order → code parties/judge/Act → save → retrieve.

### Search Requirements
Presiding Judge, Accused, Case Number, FE, CA, court type, Act/section.

### Documents
Order originals.

### Reports
Orders inventory by court type.

### Notifications
None required.

### Security
F01-003 on view/download; Limited spaces if the order is matter-bound.

### Integrations
Keyword/entity consume (Simple).

### Dependencies
F02-001; F03-005/F03-006 for search; F04 may link the order to a matter.

### Assumptions
Orders are court PDFs/scans supplied by Legal Cell, not generated by AI.

### Risks
Missing Presiding Judge or Accused coding weakens later search.

### Non Functional Requirements
Originals unchanged; coded retrieve.
